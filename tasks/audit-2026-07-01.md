## Executive Summary

**Engineering health grade: A−.** This is a genuinely well-built macOS app. Running blind to the June audit, six of seven auditors independently confirmed the codebase is hardened: **zero critical or high** engineering findings survived verification. Swift 6 strict concurrency, no reachable production force-unwraps/`try!`/`fatalError`, disciplined AES-256-GCM + Curve25519 crypto, a fully SHA-pinned CI that actually gates (build + strict lint + tests + coverage, no `|| true` masking), and a defense-in-depth release pipeline with downgrade/rollback protection. Most of the June audit's Critical/High list is closed: CI is green and pinned, `EmbeddingStore` is now an actor, OCR is a single Vision pass, every stealth window has a `sharingType == .none` test.

**The one finding that would have driven a code change was refuted by the red-team.** An auditor flagged the `caloura://capture/*` URL routes as an unauthenticated screen-content exfiltration primitive (high). Verification found the `caloura://` scheme is **not registered** (`CFBundleURLTypes` absent from source Info.plist, `project.yml`, *and* the built `.app`), so no external process or browser can reach the handler. It drops to a **low/latent hardening note**.
> **Resolved 2026-07-01 (branch `remove-dead-url-scheme`):** The entire scheme was deleted rather than gated — `URLSchemeHandler.swift` (419 lines) + its test file + the `NSAppleEventManager` GetURL registration in `CalouraApp.swift` + the CODEMAP claims. It was non-functional (unreachable), competitively undemanded, and a latent foot-gun (a future `CFBundleURLTypes` addition would have re-armed the unauthenticated capture surface). Build + `swift test` (792 pass) + lint all green after removal. This closes finding #29 below; finding #37's `URLSchemeHandler.swift` example is now moot, though its core (crypto/license files ungated) stands.

**Where "best screenshot tool" is actually won: the product gap, not the code.** Against CleanShot X, Shottr, Xnapper, Snagit, and the macOS 26 built-in tool, Caloura is missing the two features that define the paid category — a real annotation editor (text + blur/pixelate) and scrolling capture — while its three genuine moats (on-device irreversible PII redaction, encrypted + semantically-searchable history, exam-platform stealth) are hidden (redaction ships **off by default**), under-built (history hard-capped at **50 items**), and unmarketed. The engineering is ready; the product roadmap is the lever.

**Top 3 engineering items:** (1) close the latent URL-scheme authorization seam or delete the dead scheme; (2) point the coverage gate at the crypto/security files it currently ignores; (3) fix persistence write-amplification (`EmbeddingStore` full-file rewrite per capture + main-actor full-history JSON encode).
**Top 3 product moves:** (1) ship a real annotation editor (text, blur/pixelate, numbered steps); (2) scrolling capture; (3) flip the privacy moats from buried toggles to the marketed headline (PII-on-by-default w/ review, configurable + marketed encrypted history, native Share Sheet).

## TRACK A — Engineering findings (ranked, post-verification)

No Critical. No High. All engineering items are Medium or below after red-team.

### Medium

- **[medium][latent — not live] URL-scheme capture routes are unauthenticated + default clipboard auto-copy.** `URLSchemeHandler.handleCapture` (`URLSchemeHandler.swift:221-248`) requires no token, while `copy/*` routes are token-gated (`:308-317, 321-347`); `autoCopyToClipboard` defaults `true` (`AppSettings.swift:287`) and `CaptureExecutionService.distributeCapture` (`:290-311`) writes the image to `NSPasteboard.general`. **Not exploitable as shipped** — the `caloura://` scheme has no `CFBundleURLTypes` registration (verified in `Caloura/Resources/Info.plist`, `project.yml:63-83`, and the built `Caloura.app/Contents/Info.plist` via PlistBuddy → "Does Not Exist"), so `open caloura://…` and browser click-throughs never route to the app; each capture also shows a visible 6s `QuickAccessOverlay` and is throttled 0.5s. **Activation condition:** the file header + `codex/CODEMAP.md:4` + README frame these routes as intended external automation — if `CFBundleURLTypes` is ever added to make the scheme work, the copy-route token model is bypassed via the shared pasteboard on the very first capture route. *Fix: decide the scheme's fate now — either gate capture-initiation the same way copy routes are (per-launch token / explicit confirmation) before registering it, or delete the handler + CODEMAP/README claims as dead intent.*

- **[medium] `EmbeddingStore.save()` rewrites the entire encrypted file on every capture.** `EmbeddingStore.swift:84` re-encodes the whole embedding set (JSONEncoder) + re-encrypts + atomic-writes on every `add`, invoked once per capture — ~50× write-amplification at the 50-item steady state. *Fix: coalesce/debounce persistence (the actor already serializes) or append incrementally.*

- **[medium] `AppState.saveHistoryNow` JSON-encodes the full history on the main actor.** `AppState.swift:232` runs `JSONEncoder().encode(itemsCopy)` for the ≤50-item history (each carrying full OCR text) synchronously on the main actor before handing bytes to the worker — a CPU-bound main-thread stall per debounced save. *Fix: move the encode into the persistence worker actor / a detached task; only a Sendable snapshot should cross the hop.*

- **[medium] Pooled overlay windows retain full-screen frozen `CGImage` while idle.** `CaptureOverlayWindowPool.release()` (`:35`) tears down handlers but never clears `RegionSelectionView.frozenImage`, so each pooled overlay holds a ~59MB-at-5K image (×screen count) resident until the next `acquire()` — indefinitely if no further area capture occurs. *Fix: nil `selectionView.frozenImage` in `release()`/`tearDownHandlers()`.*

- **[medium] Coverage gate protects the wrong files.** `scripts/coverage_gate.py:8-15` pins 6 files, none of them crypto/security: the actual Ed25519 verify path lives in `LicenseEntitlementVerifier.swift` (ungated), and `HistoryCrypto.swift`, `URLSchemeHandler.swift`, `RedactionEngine`/`PIIDetector` are all ungated — a regression gutting crypto-verify coverage passes CI green. *Fix: add those files to `DEFAULT_THRESHOLDS`, or stop advertising the gate as covering "license".*

- **[medium] `swift test` silently omits two whole test targets.** `Package.swift:32-40` declares only `CalouraTests`; `CalouraSystemTests` + `CalouraUITests` exist only in the XcodeGen scheme (`project.yml:100-129`). CLAUDE.md/AGENTS.md document `swift test` as *the* test command, so the capture/overlay/cursor system regression guards (incl. the 2.4.0 "crosshair-gone-forever" guards, `CaptureSystemTests.swift:408-482`) never run locally. *Fix: document the `swift test` vs `xcodebuild test` split, or add the system-test sources to a SwiftPM target.*

- **[medium] The release-downgrade validator's own tests run in no pipeline.** `scripts/tests/test_validate_appcast_downgrade.py` guards `validate_appcast_against_manifest.py` (the rollback/downgrade gate `publish.sh` relies on) — but no workflow and not `release_ready.sh` ever invoke pytest, so the gate's tests can silently rot. *Fix: add `python3 -m pytest scripts/tests/` to CI and `release_ready.sh`.*

- **[medium] History-encryption tests leak into the real login keychain.** `EmbeddingStoreTests.swift:64,161,177` set no `HistoryCrypto.setSecurityDirectoryForTesting` override, so DEBUG `swift test` falls through to the real keychain root key — leaving a persistent `history-root-key-v1` item, coupling results to keychain state/order, and hard-failing (no `XCTSkip`) where keychain access is denied. *Fix: set the security-directory/keychain override in `setUp`/`tearDown` like `HistoryCryptoTests` does.*

- **[medium] XcodeGen installed unpinned but checked for an exact version.** `Brewfile` installs `brew "xcodegen"` unpinned, while the "Verify tool versions" step hard-fails unless it equals `XCODEGEN_VERSION=2.45.4` (`ci.yml:55-58`, `release-smoke.yml:139-140`, `scripts/ci_tool_versions.env:7`). The next Homebrew XcodeGen bump reds-out every CI run and blocks releases until someone manually bumps the env file. *Fix: pin XcodeGen deterministically (checksum-verified artifact) the same way SwiftLint is.*

- **[medium] Two parallel capture-timing subsystems with byte-identical percentile code.** `PerformanceMetricsAggregator`/`CaptureMetricsRecorder` (`PerformanceMetrics.swift:57-63`) and `CapturePerformanceRecorder.swift:233-239` both keep ring-buffers, both track overlapping timings; `percentile(_:values:)` is byte-identical across both files and `elapsedMilliseconds(since:)` is duplicated — the p50/p95 math can silently diverge. *Fix: collapse to one recorder or extract a shared `percentile`/ring-buffer primitive.*

- **[medium] Agent-facing docs materially misdescribe key storage (injected misinformation).** (a) `README.md:50-51` says the history key lives at `~/Library/…/security/history.key`; production stores the root key in the **Keychain** (`HistoryCrypto.swift:111,117-157`), the file path being a DEBUG-only test hook (`:103-109,159`). (b) `AGENTS.md:23` + `CLAUDE.md` "No Keychain for runtime persistence — use `HistoryCrypto.encrypt()` instead" is self-contradictory: `encrypt()` → `getOrCreateKey` → `getOrCreateKeychainKey` uses the Keychain. Intent is defensible (only one non-interactive root key; runtime data is on-disk AES-GCM), but the wording sends agents the wrong way. *Fix: correct README to "Keychain-backed (file-backed only in DEBUG)"; reword the rule to scope it to license/app-state data, not the crypto root key. (README's `history.enc` payload path is accurate.)*

### Low / nits

- **[low] Dead capture path in the core protocol.** `captureAreaInDisplaySpace(_:)` (`ScreenCaptureManager.swift:16,532`, `+SCKCapture.swift:391`, `+CLICapture.swift:164`) has zero call sites yet is a `ScreenCaptureManaging` requirement forcing every conformer + the test fake to carry it. *Delete the method, its two helpers, and the protocol requirement.*
- **[low] Five-way NSPanel overlay-config copy-paste with privacy-critical members.** Identical setup (`excludeFromScreenSharing()`, `collectionBehavior`, etc.) across `QuickAccessOverlay`, `PinnedScreenshotWindow`, `CountdownOverlay`, `CaptureOverlayWindow`, `ScreenSelectionOverlayWindow`; the `excludeFromScreenSharing`/`collectionBehavior` pair must stay identical everywhere. *One `NSPanel.configureAsOverlay(...)` helper.* (`primeCrosshair()` is also duplicated and already diverged.)
- **[low] Orphaned entitlements file makes the documented sandbox spike a no-op.** `Caloura.entitlements` exists but no `CODE_SIGN_ENTITLEMENTS` is set in `project.yml`/`pbxproj`, so it's never applied; the `SANDBOX-DECISION.md:66` spike ("set `app-sandbox = true` in the file") would silently fail to enable the sandbox. *Wire `CODE_SIGN_ENTITLEMENTS` or delete the file + correct the doc.*
- **[low] Smart-crop is awaited before the first-pixel preview.** `CaptureExecutionService` awaits `SmartCropper` (Vision saliency, 300ms timeout + full-image border scan) before `publishRawPreview`, adding latency to the headline capture-to-feedback metric when auto-crop is on. *Publish raw preview first; replace with cropped result async.*
- **[low] Cursor micro-loops & unbalanced observers.** `CaptureCursorController.scheduleMaintenanceReprime` (`:191`) push/pops `NSCursor` ~20×/sec during a selection session (event-drive it instead); its `init` registers two `NotificationCenter` observers with no `deinit` removal (leak-shaped if instances ever become transient).
- **[low][unknown reachability] Timeout cancellation-race hang.** `Timeout.swift:14-53` — cancellation delivered in the sub-µs window before `coordinator.install(continuation)` can strand the continuation (rare hang, never a crash; e.g. `SmartCropper.autoCrop` never returns, `isCapturing` stuck). *Re-check `finished` under the lock after install and resume with `CancellationError`.*
- **[low][unreachable today] Enrichment-queue stranding.** `CaptureEnrichmentCoordinator.enqueue` (`:19-24`) orphans `pendingOperations[id]` when the ID is already running; latent only (the sole re-enqueue caller is gated by the `alreadyEnriched` phase check).
- **[low] Stale "Gumroad" production description.** `docs/SANDBOX-DECISION.md:30,48,70` and `release.sh:4,652` describe license verification as Gumroad; Release actually verifies against the signed Cloudflare Worker (`LicenseEntitlementVerifier.swift:29,54,211`), Gumroad being a `#if DEBUG` fallback. *Update doc/script comments to the signed-backend model.*
- **[low] Perf-baseline tests run in the default `swift test`.** `PerfBaselineOCRTests.swift:66-67` etc. assert only a self-labeled "sanity bound, not a perf gate" (effectively non-failing) yet add time + Vision flake to every run. *Move to an opt-in perf harness.*
- **[low] Missing license-verify negative tests.** No test for the backend host-mismatch rejection (`LicenseEntitlementVerifier.swift:69`) or for signature-byte tampering with the correct key. *Add a redirect-to-other-host case and a flip-signature-byte case.*
- **[low] `HistorySearchModel` CacheKey deep-compares full OCR text.** `:5` — every SwiftUI body eval pays an O(total-text) `Equatable` compare + holds a second strong ref to all history text. *Key the cache on a cheap revision token.*
- **[low] Missing xcodegen-drift gate + Package.resolved schema mismatch.** No CI step asserts committed `.xcodeproj` matches `xcodegen generate`; root `Package.resolved` is schema v2 vs xcodeproj v3 (pins identical — cosmetic, will re-churn on resolve).
- **[low] Test-only getters & bare-sleep syncs.** `budgetViolationCount(for:event:)` (`CapturePerformanceRecorder.swift:152`) is test-only with no production consumer; fixed `Task.sleep` negative-syncs in `WindowPickerManagerTests.swift:126`, `ScreenshotArtifactCoordinatorTests.swift:57`, `CaptureFreezeServiceTests.swift:41` can flake under CI load.

### Refuted / corrected during red-team (do NOT act on these)

- **URL-scheme "silent exfiltration" (originally high) → refuted.** Scheme unregistered (no `CFBundleURLTypes` in source or built `.app`); external callers cannot reach the handler; every capture shows a visible overlay + is throttled. Demoted to the latent Medium above.
- **"Captures always persist to encrypted history" → false.** History write runs only inside the `autoSaveToDisk == true` branch *and* only after a successful disk save (`CaptureExecutionService.swift:94-103,235-254`; default `false` at `AppSettings.swift:288`; test-confirmed `CaptureExecutionServiceTests.swift:141-185`). Default config: a capture reaches only in-memory `lastScreenshot` (300s auto-wipe) + clipboard.
- **Correctness/crash & CI-gating "clean" verdicts → survive verification.** No reachable production `fatalError`/`try!`/force-unwrap (all hits are `init?(coder:)` boilerplate or compile-time-constant guards); `ci.yml` triggers on push+PR and every gate can fail (no `|| true`/`continue-on-error`).

### Clean dimensions (verified strengths — preserve)

Crypto (AES-256-GCM + HKDF domain separation, non-sync `…ThisDeviceOnly` keychain root key, `O_EXCL` atomic key create), license path (Curve25519 signature verify, Release forces signed backend, downgrade/tamper `migrationLocked` guard), Sparkle chain (2.8.1 exact-pinned, EdDSA appcast, no known CVE), secrets hygiene (no private material committed, `certs/` gitignored + public-only, action SHAs pinned even in secret-holding workflows), process execution (argv arrays, no shell), path safety (`FileOrganizer` `..`+symlink validation), the 7-state permission machine (exhaustive decision-table, 577 lines of tests), and window stealth (applied only to Caloura's own windows). Outbound network is HTTPS-only to license + Sparkle; no telemetry phones home.

### Ranked product gaps

Severity here = **product-adoption impact** (an evaluator comparing to CleanShot), not code-defect severity.

**Adoption blockers (an evaluator churns immediately)**
1. **Annotation editor is 3 tools with no Text and no Blur/Pixelate** (`AnnotationOverlay.swift:57-69` — exactly `.arrow/.rectangle/.highlight`). Text labels and blur are the two most-used markup tools in every competitor; a user annotating a bug report or hiding a value abandons on first edit. *Add text, blur/pixelate, numbered-step, line/ellipse.*
2. **No scrolling capture** (`CaptureMode.swift:3-6` — area/window/fullscreen only; no stitch path). Caloura's own personas (Code Snippet, Lecture Notes, chat) routinely exceed one screen; CleanShot/Shottr/Snagit all do this and people buy specifically for it. *SCK-based scroll-and-stitch.*

**Table-stakes gaps shared by all major paid rivals**
3. **No screen recording / video / GIF** (no `AVAssetWriter` anywhere; `SCStream` is single-frame). CleanShot, Snagit, and even the free built-in record. *Add MP4/GIF via SCStream — the biggest lift, category-defining.*
4. **No cloud upload / instant share link** (no upload backend). CleanShot's flagship, Xnapper's most-requested gap. *Optional share-link tier (e.g. Cloudflare R2).*
5. **No native macOS Share Sheet** (no `NSSharingService`/`ShareLink`). Blocks send-to-Messages/Mail/Notes. *Wire `NSSharingServicePicker` into the post-capture overlay + history — cheapest of the five.*

**Under-leveraged moats / opportunities (this is the wedge)**
6. **Encrypted searchable history is a hidden, non-configurable 50-item buffer** (`AppState.swift:62` `private let maxRecentItems = 50`, no setter/binding). The strongest moat vs the new wave of on-device screenshot archivers can't function as an archive. *Raise/configure retention; market encrypted semantic search as a headline.*
7. **The best differentiators ship hidden.** PII auto-redaction is **default OFF** (`AppSettings.swift:311`) and absent from README highlights; stealth + encryption aren't surfaced in onboarding. *Default PII on (with the existing review overlay); lead marketing with privacy/redaction/stealth.*
8. **"Beautify" is 5 gradients, no image backgrounds / window frames / custom editor** (`BeautifyTheme.swift:33-105`). Xnapper/others win on 160+ backgrounds + browser-frame mockups. *Add image backgrounds, window/browser frames, a custom-theme editor.*
9. **No color picker / pixel ruler.** Shottr's praised niche and a top CleanShot request — cheap way to win designers/devs.
10. **Direct-download only, no App Store / Setapp reach.** Un-sandboxed design blocks the Store; *pursue Setapp for discovery.*
11. **Presets are read-only** (`PresetManager.swift` — no create/edit/delete API); limits the "workflow" pitch.
12. **Positioning drift:** "students and educators" (`PreferencesView+Tabs.swift:173`) under-sells the PII/stealth/encryption strengths that appeal to the category's paying core (designers/devs/support).

### Path-to-best-in-class verdict

Two fronts. **(1) Close table stakes** to stop evaluation-stage churn — scrolling capture, a real annotation editor (text + blur/pixelate + numbered steps), and a native Share Sheet + optional share-link tier; video/GIF is the larger follow-on. **(2) Own the wedge no incumbent occupies** — "the private screenshot tool: everything on-device, auto-redacted, encrypted, and instantly searchable." Turn PII-on-by-default, unlimited (or configurable) encrypted semantic history, and stealth capture from buried toggles into the marketed headline. The engineering foundation is already strong enough to build both on; the differentiators exist but are invisible and capped — surfacing and finishing them is higher-leverage than any single new capture mode.
